The Story Behind the Code

This comic illustrates how the Sky Combat game's aircraft manager uses formal verification patterns to guarantee memory safety. Instead of hoping that array accesses are valid, we prove they are valid using Truth Buckets.

Key Safety Mechanisms

  1. Truth Requirements: Every function that accesses the aircraft array must first verify preconditions using TRUTH_REQUIRE macros.
  2. Bounds Checking: The verify_aircraft_count_bounds function ensures the aircraft count never exceeds MAX_MANAGED_AIRCRAFT (16).
  3. Safe Wrappers: The aircraft_manager_get_safe function wraps unsafe operations with verification checks.
  4. F* Type System: The formal specification uses dependent types to make invalid array access impossible at the type level.

Real Code Example

// From aircraft_manager_truths.c managed_aircraft_t* aircraft_manager_get_safe( aircraft_manager_t* manager, int id, truth_bucket_t* truth) { /* Build truth requirements */ TRUTH_REQUIRE(truth, "manager is not null", manager != NULL); TRUTH_REQUIRE(truth, "id >= 0", id >= 0); TRUTH_REQUIRE(truth, "manager has valid count", verify_aircraft_count_bounds(truth, manager)); TRUTH_REQUIRE(truth, "id < aircraft_count", id < manager->aircraft_count); /* Safe to access */ managed_aircraft_t* result = &manager->aircraft[id]; /* Ensure postconditions */ TRUTH_ENSURE(truth, "result is not null", result != NULL); TRUTH_ENSURE(truth, "result is within array bounds", (result >= &manager->aircraft[0] && result < &manager->aircraft[MAX_MANAGED_AIRCRAFT])); return result; }

Why This Matters

By using Truth Buckets, we transform runtime crashes into compile-time or early-runtime failures with clear error messages. The system not only prevents segfaults but also documents why the code is safe, making it easier for future developers to maintain.
